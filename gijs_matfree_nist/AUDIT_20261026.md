# Full code audit, 2026-10-26

Audit target: the original crate `gijs_matfree` (19 files, 15,007 lines),
as it stood on 2026-10-26, before any changes. The audit was read-only.
No audit finding was fixed in the original crate, and no audit fix is
in the NIST build either, except where explicitly noted below. The
NIST build changes only the RNG (see README_NIST.md), plus the later
`reuse-holdout-test` command. Everything else in the NIST build is the
audited code, with the mechanical `Rng(x)` to `Rng::new(x)` change.

Commissioned by Jacob, 2026-10-26, after the ID-0 flag-none
investigation and the discovery that the original RNG was xorshift64.
Reported batch by batch as each batch landed. This file compiles those
six batch reports into one place. File and line numbers refer to the
original crate; the NIST copy has the same lines except for the RNG
call-site change.

## Headline

- No arithmetic bug was found in the core elimination logic: jet/Hasse
  construction, the dense distinguisher, the left-kernel reuse
  criterion, and the holdout echelon test are mathematically correct
  for well-formed inputs at the sizes used.
- The one load-bearing correctness bug in key generation was the RNG
  itself (F0 below). Everything else that matters is about verdicts,
  spool identity, seed handling, and boundary cases in Phase 2, not
  about the jet math being wrong.
- Two verdict traps affect how past results must be read:
  `verify` never checks unmixing, and its pair check is vacuous on a
  flag-none run, so a verify PASS on a flag-none run cannot be read
  as pairs found. Puncture spools carry no key identity, and
  frequency/cluster spools carry no parameter binding, so a reused
  output directory could silently mix runs.
- The xorshift RNG is the root cause of the ID-0 SR collapse, and it
  is fixed only in the NIST build. It does not explain kp28 flag-none
  at w=30, which is a different regime.

## Batch 1: attack.rs, main.rs, Cargo.toml

### Critical

- **A1. `verify` never checks unmixing.** `attack.rs:1826` parses
  `--unmixed` into `unm` and never reads it again; `cmd_all`
  discards the `do_unmix` return. `ATTACK SUCCEEDED` certifies
  pair-finding plus SS only. A run unmixing 0/33 could print it.
  Past effect: the q=256 33/33 pair count was reported separately
  from the verdict, so that count stands, but the verdict alone
  does not certify unmixing.
- **A2. `verify` pair check is vacuous in flag-none.**
  `attack.rs:1861-1877`: a pair counts as non-degenerate only if
  both members were flagged at least once; unflagged true pairs
  leave the denominator as "degenerate skipped". Flag-none gives
  0/0 = PASS. Any verify PASS on a flag-none run cannot be read
  as pairs found.
- **A3. Unknown CLI flags silently ignored in `attack.rs`.**
  Hand-rolled parser `attack.rs:89-117`. Typos like `--thread` or
  `--trial` run with defaults; duplicated flags use the first
  value. `main.rs` does reject unknown flags. This is a structural
  cause, see A19.

### High

- **A4. Puncture spools have no key identity.** Header
  `attack.rs:929-1000` carries nprime, s, d, size, puncturings,
  seed, shortening only. A reused out-dir with a different key at
  the same parameters and phase seed silently loads the old key's
  pairs. ID-0 batches were fresh directories, so this is a live
  trap, not a demonstrated contamination.
- **A5. Seed defaults are inconsistent.** Keygen 42, phase1 100,
  `all` 42 but passes seed+1000 to Phase 1, holdout-test 100,
  puncture-test 100, puncture seed seed+1,000,000. Under
  `all --seed 42` the actual puncture seed is 1,001,042. Usage
  text never mentions the +1000. Config records phase seed 1042,
  not user seed 42.
- **A6. The 8 GiB reuse guard is per-factorization, not per-run,
  in puncture** (`attack.rs:1090-1095`, no times-threads). The
  tool would accept 20 threads times 1.75 GB, about 35 GB.
- **A7. `puncture-test` default puncture size is 50 percent of
  nprime** (`attack.rs:2385-2392`), not 4 as in Phase-1 puncture.
  Comparing the two without an explicit `--puncture-size` is
  apples to oranges.
- **A8. `main.rs:248-260` prints GIJS dimensions and the 2 GB
  guard with the original k, not kprime.** It overstates; trial
  results are unaffected.

### Medium

- **A9.** Planning-fail override proceeds with y-margin 0, the
  loosest filter (`attack.rs:313-323`).
- **A10.** No nprime <= N validation; the kprime check passes
  when nprime > N.
- **A11.** No range validation for s, d, q, n, k, w.
- **A12.** `main.rs` H2' serial test treats a gapped subsequence
  as consecutive trials.
- **A13.** `main.rs --search` is truncated and biased
  (descending, nprime >= 20, kprime >= 8, first 20 only).
- **A14.** Parse errors panic as "bad int" / "bad float" with
  no flag name.

### Low

- **A15.** `do_ss` config records `phase2=fast` even on
  fallback to scan.
- **A16.** `bootstrap_scan` has no cost guard (q^need about
  10^9 at q=1024, need=3); parallel first-found is nondeterministic.
- **A17.** Verify SS check is partly circular (stacks pure
  columns against GRS from SS's own output); round-trip only
  over pure positions, fixed seed `Rng(20261019)`,
  t = (n_pure - k - 2) / 2.
- **A18.** `main.rs --self-test` silently overwrites user flags
  (fixed `selftest_out` directory, so no clobber).
- **A19.** Cargo: no argument-parsing library (structural cause
  of A3), rayon unpinned `1`, package named `rlce-test` though
  `rlce-attack` is the primary binary.

### Clean in these files

Mode, engine, and phase2 parsers reject unknown values. Puncture
pairs are only exact intersections, greedy disjoint, unresolved
columns go to candidates and are never guessed. Cluster orphan
fallback prints PHASE 1 INCOMPLETE. Spool writes are atomic
temp+rename, header mismatch forces recompute (the gap is only
missing key identity, A4). `verify` does check false positives
and exits 1. `main.rs` parser rejects unknown flags. H1 rates
restrict to intact-pair observations.

## Batch 2: rng.rs, rlce.rs, keyio.rs, gf.rs, linalg.rs (665 lines)

- **F0. Xorshift64 is the RNG, and it caps R rank at 64.**
  `src/rng.rs`, 64-bit state, shifts (13,7,17), one instance for
  everything in keygen order. Output is F2-linear, so the
  field-element sequence satisfies a linear recurrence of order
  64 over GF(1024), and all R windows span at most 64 dimensions.
  Once w > 64, R vectors must be dependent. ID-0 w=160 collapses;
  kp28 w=30 and q256 w=33 sit below the cap and look independent.
  This is the root cause of the ID-0 SR collapse (post-shortening
  SR rank about 10). Fixed only in the NIST build, by CTR_DRBG
  with AES-256. It does not explain kp28 flag-none at w=30.
- **F1. Seed 0 hangs keygen silently.** `Rng(0)` is always 0;
  GRS x=0 is rejected forever, the GL loop never exits. No past
  run used seed 0.
- **F2. Keys from different seeds are not independent
  replicates.** The xorshift stream is linear in the seed
  (stream(42) XOR stream(43) = stream(1) until the first
  seed-dependent rejection). This weakens "seeds 42/43/44 agree"
  as evidence, and the ID-0 seeds 42/43/100 R-rank agreement
  (all 64 is expected, not three independent confirmations).
- **F3. One stream for every keygen component.** One point of
  failure, draw order undocumented. This is the delivery
  mechanism for F0.
- **F4. The only real correctness bug in this batch.**
  `linalg.rs:10-12` `kernel_basis` returns (0, empty) for zero
  rows; the kernel of a 0-row matrix is the whole space
  (dimension k). An empty-hit shortening would silently give
  length-0 columns. Never hit in past runs (hits 424, 50, etc.).
- **F5. keyio.** Write length checks are `debug_assert` only
  (release writes silently, shifting columns). Reads validate
  almost nothing (no value < q, pure iff pair_id = -1,
  pairs versus pair_id, trailing bytes). **No seed, hash, or
  provenance is stored in either file**, which is why the
  identity audit had to regenerate and hash-compare.
- **F6. GL doc/code transpose mismatch.** `rlce.rs` doc
  [[a,b],[c,d]] versus code c1 = a*g + c*r, c2 = b*g + d*r.
  Distribution is unchanged (determinant same, entries iid),
  not a statistical bug. Pairs are rebuilt in public order, so
  `pairs[p].0` may be c2, not c1. Past SR work used
  transpose-aware asserted reconstruction and is unaffected.
- **F7. Modulo bias in `below()` is real but at most 1 part in
  10^16, zero for n=1024.** Explicitly not a lead.
- **F8.** `gf.rs inv(0)` / `pow` fail loud (panic), unreachable
  from these call paths.
- **F9.** Two tests assume more randomness than the RNG provides
  (for example `kernel_dim` asserts rank exactly 5 from
  `Rng(123)`).

### Clean in these files

GF arithmetic (primitive polynomials m=5..11, LFSR step,
exp/log, prime-factor lists; primitivity tests are genuine
proofs). Both Fisher-Yates implementations (no off-by-one).
GL rejection sampling is uniform over GL(2) conditional on a
good RNG (about 2/q rejection). GRS construction (distinct
nonzero x, y in 1..q-1, y*(1,x,...,x^(k-1))). Twin construction
and exactly-2-members rebuild. Shortening (kept = complement
of hit, ascending, S times column correct). Kernel RREF except
F4. Key format code and docs agree, `read_exact` so truncations
error. Model point: biased draws in support, multipliers,
twin-set, GL, or permutation make a key atypical, not invalid;
within these files only the R draws (via F0) break the GIJS
independent-uniform model.

## Batch 3: matfree.rs (4,480 lines)

Blast radius first: this file is opt-in (`--engine bw-sigma`).
Frequency defaults to Dense, cluster and puncture to Reuse
(`reuse.rs`). `reuse_bw_flags` has no non-test caller. The q256
33/33 run and the ID-0 reuse spools did not use this file and
are not invalidated by this batch.

### High

- **F1. Exhaustion returns `true` (GRS) in all three
  distinguishers** (scalar `:614-683`, cap 32 / streak 4; BW
  `:2177-2206`, cap 8 / streak 4; sigma `:2615-2644`). The
  claimed q^(-samples) bound only holds if that many
  independent certified vectors were tested; exhaustion may
  test fewer or zero. One-sided bias toward GRS / flag-none.
- **F2. Toeplitz cap `BW_MAX_TOEPLITZ_WIDTH=6144`**
  (`:1708,1926-1932`) makes the Toeplitz path always fail at
  flagship (ID-0 (2,3) needs about 16,704; (3,5) about
  140,883), falling through to F1 `true`.
- **F3. Sigma empty pool reported `Invertible`, hence `true`,
  with no retry** (`:2366-2369`). The pool is a
  filter-surviving subset; a systematic filter miss masquerades
  as invertibility.
- **F4. `reuse_bw_flags`: 64-dimensional sampling ceiling.**
  Pinned test: pool rank at most 64 < J=91, all taus flagged
  while dense unflags them. Stop criterion is global pool rank,
  not per-tau. First-run Failed/Invertible breaks with an empty
  pool and flags every tau with no error. The non-pool version
  discards the pool diagnostic. No past production use.
- **F5. "Independent certified vectors" are counted, not
  ranked** (`:670-677`, `:2134-2140`). Dependent separators can
  reach the count, overstating the q^(-samples) bound. The
  `false` side is still certified.

### Medium

- **F6.** `Invertible` inference is heuristic (a projection
  can miss a kernel vector), never retried.
- **F7.** Escalation is terminal on first failure once Lb >= n
  (no fresh-block retry).
- **F8.** Pool truncation to 160 is systematic, not random
  (first 160 nulls / first 80 sigma rows; later rows dropped).
- **F9.** Sigma memory cap counts terms only, not b (budget
  holds only at b=32; Toeplitz path doubles the matrix via
  copy in `nullspace_flat`).
- **F10.** Distinguisher seed derivation omits (s,d,k,q), so
  (2,3) versus (2,4) comparisons reuse the same underlying
  stream, not independent draws.
- **F11.** `matvec_mt` / `matvec_mt_block` silently compute
  full M^T, not M_tau^T (correctness relies on the caller
  zeroing the excluded block; in-file tests compare full
  versus full, masking the trap; no in-file caller violates it).
- **F12.** `matvec_m_block` silently truncates on length
  mismatch.

### Low

- **F13.** All-zero start-vector fallback is deterministic
  (sets v[0]=1; probability q^(-n)).
- **F14.** Misleading stats (verified overwritten per batch,
  pool = raw samples).
- **F15.** Differential tests never reach flagship (k <= 19,
  q <= 128, n <= 41, 8 taus; no (2,3) kprime=46 q=1024 test; no
  `reuse_bw_flags` J>64 test except the pinned failure).
- **F16.** Several "benchmark" figures are extrapolations or
  formulas, not measurements; the scalar path is infeasible
  well below flagship yet remains public API.
- **F17.** Scalar BM early termination heuristic, truncation
  to Failed to F1 `true`.

### Clean in this file

JetOp / Hasse submask plus char-2 coefficient 1 matches
`gijs::hasse`. BM, `conn_to_mu`, pass-2 formula correct. All
defect / radical cancellation paths re-verify Mz == 0 / Az == 0
exactly before use, so every `false` decision in this file is
certified. `nullspace_flat` is valid. Euler degree estimate is
an upper bound. Toeplitz window rows 1..=L correct. Sigma dual
candidates use both shifts, both verified. Parallelism is
disjoint / XOR-reduced. Inputs are not mutated.

## Batch 4: gijs.rs, reuse.rs, holdout.rs, mat.rs (1,619 lines)

Headline: no arithmetic bug in the core elimination logic.
Jet/Hasse, the dense distinguisher, the left-kernel reuse
criterion, and the holdout echelon test are all mathematically
correct for well-formed inputs at the sizes used.

- **F1 (medium). Holdout "random control" is not random.**
  `holdout.rs:324-328`: control = first kept column that is
  neither tau nor mate (for ID-0 sh23, control = original
  column 1 for all three taus). `in_without_random=3/3` only
  shows that one column is dispensable. It does not affect
  `in_without_mate` or the random-vector results.
- **F2 (medium). Holdout pair test mixes methods.**
  `in_with_mate` comes from reuse
  (`holdout.rs:257-258,351`), `in_without_*` from dense. The
  tool is presented as a dense check on reuse, but one of three
  outputs is reuse itself. ID-0 sh23 is safe by monotonicity
  (dense in_without_mate=true implies in_with_mate=true). But
  the kp28 nprime=115 "mate essential" claim is reuse-dependent
  at that scale (supported by small-scale differential tests,
  not dense-verified there by this tool). Note: the later
  kp28 nprime=112 dense pair (in_without_random versus
  in_without_mate, both dense) does prove mate essentiality
  without reuse, and the new `reuse-holdout-test` gives the
  same three verdicts from one Pperp factorization.
- **F3 (low).** Pair tests are the first P in kept order, not
  a random sample (weakens generalisation, does not falsify
  the 3 pairs).
- **F4 (low).** Holdout reports M_full rank/codim, not M_tau
  (difference at most J=47, negligible against codim 6157).
- **F5 (low, latent).** Exponents stored as `u8` in `enum_exp`
  (`gijs.rs:26-37`), silent truncation if d/s > 255, impossible
  at used parameters (d <= 5, s <= 3).
- **F6 (low).** No memory guard inside `reuse.rs` itself; the
  estimate function is correct and conservative (counts
  worst-case Pperp), so the consequence is false rejection,
  for example ID-0 (2,4) nprime=367 guard-rejected at about
  9.4 GB estimated while true Pperp is smaller.
- **F7 (low).** Differential tests only small (reuse k <= 19 /
  n <= 14, holdout k <= 12 / n <= 12) and not in ID-0's regime.
  Flagship equivalence is extrapolated via scale-independent
  proofs plus exact arithmetic, plus Jacob's external sh23 run
  (3 taus), not tested in-file.
- **F8 (low, derivative of the known RNG issue).** Holdout
  random vectors drawn from `Rng(trial_seed ^
  0x9e3779b97f4a7c15)` (`holdout.rs:265-269`) whose comment
  claims independence. That claim rests entirely on RNG quality.
  At ID-0 (20 vectors length 46, codim 6157) the 0/20 result is
  robust; no past result is overturned.
- **F9 (low).** Malformed or degenerate inputs panic (not
  silent bias) across all four files.
- **F10 (low, cost).** Holdout recomputes the same dense
  elimination about 9 times per trial with 3 pair tests, which
  is why the ID-0 holdout was overnight.

### Clean in these files

Hasse/Lucas (including e=2,a=1 to 0). Enumeration counts match
J, N_d, same code in all three files (no jet-order divergence).
Dense early return on a non-pivot column is correct (later
eliminations cannot reintroduce a nonzero). Reuse left-kernel
criterion is exact; empty Pperp implying every tau flagged is
a proved consequence (full row rank), not a silent default.
Holdout echelon test is correct. Seed mapping for holdout
(`base+1+t`) matches phase1 (`seed+1+t`), kept sorted
ascending, index mapping correct (sh23 `--seed 1065` targets
the right shortening). No thresholds, sampling, approximations,
floating point, or tolerance in these four files. No overflow
at flagship sizes. `mat.rs` dense algebra is all correct for
well-formed inputs.

## Batch 5: phase1.rs, puncture.rs, cluster.rs

Scope note: the puncture planner (p_both, p_single,
shortenings/puncturings) and greedy-disjoint aggregation live
in `attack.rs`, not in these files. This batch audited the
frequency planner (phase1) and the cluster planner (cluster)
fully, using attack only as caller context.

- **F1 (medium). Puncture positions repeat identically across
  shortenings.** `puncture.rs:259-260`: seed = puncture_seed
  + j only, no shortening term. Callers pass the same puncture
  seed per shortening, so puncturing j hits the same
  kept-order positions in every shortening. Exact-vote counts
  across shortenings are not independent draws while
  aggregation treats them as independent votes. True even
  with a perfect RNG. It does not explain ID-0 zeros; it does
  weaken vote-independence behind the kp28 puncture 5/5
  validation vote counts and future vote ranking. Fix
  direction (not applied): seed by (sh, j).
- **F2 (medium). Frequency/cluster spools have no parameter
  binding.** `phase1.rs:954-985,1067-1075`: trusted on resume
  iff a single line, strictly increasing indices, correct
  count, trailing newline. No header with nprime, s, d, seed,
  or engine. The doc comment itself says reusing a directory
  with different parameters is "a user error (stale files
  would be trusted)". Unlike puncture spools (exact-match
  header in attack.rs), a reused out-dir silently mixes
  trials. Contamination is undetectable from spools alone. No
  evidence past runs reused directories this way (normal
  `all` uses a fresh directory), but it cannot be ruled out
  retrospectively.
- **F3 (medium robustness). Cluster aggregation validates
  nothing.** `cluster.rs:285-300`: ignores `nums[0]`, never
  checks count, sorted/distinct/< n_pub (only debug_assert),
  or completeness. An empty file is a legitimate empty trial.
  One torn/truncated trial file flips pattern bits for every
  column flagged in it, splitting true pairs into
  orphans/oversized and losing pairs (frequency damage is
  milder: underestimated |V| diluting separation). Normal flow
  recomputes torn files before aggregation, so completed
  toy/validation runs are unaffected. It bites only if a
  killed run's directory is aggregated without re-running.
- **F4 (low-medium). Puncture intersections are fragile to
  one false-positive flag.** `puncture.rs:289-300`: the first
  flag sets the intersection, later flags only intersect (can
  only shrink, never recover). One flag where the mate was
  not punctured permanently kills that shortening's vote for
  the true pair, and no confidence signal (survived 50 versus
  2) is emitted. The code matches the specified method; this
  is design fragility, not a mapping error. No past effect
  (kp28 puncture false-positive rate 0; ID-0 flags 0).
  Cross-file note: the puncture voter in `attack.rs` accepts
  a pair on a single exact vote in a single shortening, no
  quorum. A spurious singleton intersection from 2 flags
  (a few percent per column per shortening at p=4, nprime=366)
  could enter `pairs.txt` on a tie.
- **F5 (low).** Cluster planner polishing loop guard 16 can
  return an unverified trial count for extreme parameters.
  Toy/validation counts are pinned and within 1; no past
  effect.
- **F6 (low).** Cluster planner reports two 0.01 bounds as
  one; union bound total at most 0.02.
- **F7 (low).** Oversized cluster groups (>2) go to `oversized`
  only, not pairs, not pure, and no candidate file in cluster
  mode (unlike puncture candidates). Members silently vanish
  downstream. None at toy/validation.
- **F8 (low).** Orphan fallback checks only the first
  coordinate (`cluster.rs:523-526`) despite a comment claiming
  a shape check. It cannot cause false resolution, since
  `resolved` is hardcoded `None`; it affects only reported
  passing counts.
- **F9 (low).** `plane_roots` returns empty in the
  linearly-dependent case, contradicting its own comment
  (rank fallback lives in the resolver's count, not in the
  returned roots). Reporting only.
- **F10 (low).** `run_trials` panics on a second global rayon
  pool build (puncture path ignores the error, inconsistent).
  One mode per process in production; no past effect.
- **F11 (low).** kprime is never validated in these files.
  Out-of-range nprime underflows to huge kprime (misleading
  memory-guard failure) or asserts/panics. Crash on user
  error, not a silent wrong result. All past nprime values
  were valid.
- **F12 (low).** `tprime_max` clamps a negative threshold to
  0. The planner rejects such points; runs would record only
  empty flagged sets (honest empty).
- **F13 (low).** Explicit `--y-margin` override computes
  sneak-through failure but only warns (in the plan report,
  which `run_trials` does not print). Auto-planned runs
  (kp28, ID-0) are unaffected.
- **F14 (low, unverified).** BwSigma reuses one seed for all
  hold-outs in a trial (`phase1.rs:180-186`). The mixing claim
  lives in matfree, not verifiable here. Flagship results did
  not use BwSigma.
- **F15 (low).** Frequency tie-breaking is nondeterministic
  only in sparse mode (C(N,2) > 10^8, N >= about 14142,
  HashMap order). Flagship N=790 is dense, unaffected.

### Clean in these files

Flag-count/index mapping is correct in all three files
(reuse/dense/BwSigma: decisions[ti] to kept[ti] to original;
puncture: decisions[idx] to kept_prime_pos[idx] to kept[pos],
counts by kept-order position). Seed mapping is consistent,
no off-by-one (the only issue is F1). `tprime_max` is verified
against two pinned values (D = kprime+w-1,
J_max = floor(tprime_max/2) correct). Frequency planner core
(p_unhit, p_false_max = (nprime)_4/(N)_4, p1_min, sums,
binary searches, binomial/incomplete-beta machinery) checks
out. Cluster planner core (collision = p^2 + (1-p)^2) is
correct, counts pinned. Cluster grouping deep copies, one
group per column, no double counting. Puncture classification
(pure / singleton-hit / singleton-punctured / both-kept) is
correct. Intersection empty-for-zero-trials and flagged-before
logic is correct. Resume from `done` does not double-count
for consistent spools. Mismatched kept/done triggers a full
restart. Puncture never emits a pair, cluster never resolves
an orphan (`resolved: None` always).

Bottom line of this batch: nothing in these three files
explains ID-0 all-zero spools or kp28 results as a
mapping/counting error.

## Batch 6: ss.rs, fastss.rs, sigma.rs, unmix.rs

Scope note: `sigma.rs` is the M-Basis for matfree BW Phase-1
extraction, not Phase 2.

- **U1 (high for unmix completeness, confirmed).**
  `unmix.rs:38-56` `is_geometric` rejects every v[0]=0,
  including the exact infinity vector (0,...,0,y). The comment
  ("keygen uses nonzero x,y") is true in the original monomial
  basis but false in the SS-parametrised basis, where Mobius
  freedom (`ss.rs:110` rho loop) can send a pair's GRS
  direction to infinity. Confirmed past effect: toy `all`
  unmix 32/33, pair (12,36) at the Mobius pole. Expected about
  w/q pairs per key. Systematic small undercount at q=256/1024.
- **U2 (medium).** `unmix.rs:95` loop `1..q` excludes
  alpha=0. If c=0, alpha* = c/d = 0, c1 itself is pure and is
  never tried; returns None. Rate about 1/q per pair.
  Bootstrap scan in attack.rs does include lambda=0, an
  internal inconsistency.
- **U3 (medium).** Same loop excludes alpha=infinity (d=0):
  the pure direction is c2 alone, never tried. `fastss.rs`
  handles it via 8 orientation flips, so a pair Phase-2
  bootstrap already unmixed can still fail the separate unmix
  step. U2/U3 imply cluster validation and q256 unmix counts
  are lower bounds, not exact.
- **S1 (medium-low).** `ss.rs:138-160` panics when r = N_p - k
  = 1 (`c0[2]` out of bounds; only guard is n_p > k;
  algorithm needs r >= 2). No known past effect (real uses
  N_p = k+3 or more, tests r=9).
- **S2 (medium robustness / low correctness).** `ss.rs`
  panics on non-GRS input instead of Err in several places
  (kernel assert len 1; `inv` with no zero check; gamma zero
  aborts the whole attack instead of trying another window).
  Scan and fast paths wrap `ss_attack` in `catch_unwind`
  (panic = rejection, correct by accident); the direct path
  (`attack.rs:1656`, n_pure >= k+3) has no catch, so the same
  input crashes the `ss` command. No past effect (inputs were
  genuine GRS).
- **S3 (medium as library, low in current use).**
  `wb_decode_k` (`ss.rs:328-369`) is unsound standalone:
  takes `basis[0]` with no kernel-dim check, no monic/degree
  enforcement, truncates the quotient at k (`qlen=min`,
  `:367-368`), no re-encode/distance check. Underdetermined
  systems give an arbitrary kernel vector. The only production
  caller (verify round-trip) compares to the planted message,
  so wrong returns become FAIL, not false PASS. No past effect.
- **F1 (fastss, low).** `dual_test` rank < 2 branch is
  permissive by design (`fastss.rs:295-314`). Not a
  false-accept path (Stage 4 SS is the only acceptance test,
  with exact verification), but it weakens the filter. Its
  `dt == ss_ok` test covers only sampled wrong candidates at
  k=8, q=64.
- **U4 (low).** `unmix.rs:104-107` breaks on the first
  geometric result, no uniqueness check (fails if r itself is
  geometric with a different x, or r proportional to g;
  probability about q^(2-k), negligible at k >= 14; comment
  asserts uniqueness, never verified).
- **U5 (low).** `unmix.rs:82-93` no pair-index validation
  (i != j, range, disjointness). A false pair (i,i) could
  "unmix" a pure column. Phase-1 pairs are disjoint by
  construction, unreachable normally.
- **S4 (low).** `ss.rs:387` `to_monomial_basis` doc contradicts
  the (correct) caller (doc says m = m' * inv(Sinv); caller
  correctly uses m_rec = m' * Sinv). Doc only.
- **S5 (low).** `ss.rs:102` gamma zero aborts the whole attack
  instead of trying another window (cannot falsely reject
  genuine GRS).
- **S6 (low).** `ss.rs:110-130` SS support is finite-field
  only, no infinity point. Fine for this keygen; high only in
  interaction with U1.
- **F2 (fastss, low).** `fastss.rs:161-171` `matvec` /
  `transpose` silently truncate on ragged lengths. Production
  inputs are uniform; no false accept found.
- **F3 (fastss, low).** `fastss.rs:535-560` fixed
  J=[0,1,2], J'=[3,4,5] plus swap heuristic. Performance only;
  correctness preserved (All branch scans all l3; a true
  triple satisfies both minors).
- **F4 (interaction, in attack.rs).** `--phase2 scan` has no
  infinity handling (`bootstrap_scan` enumerates lambda in
  F_q including 0, not infinity; fails outright with "Pairs
  may be wrong" on a d=0 set). Medium for scan mode, low for
  default fast (fast already tried flips); scan tests at q=32
  never exercised it.
- **G1 (sigma, low).** `sigma.rs:87-100` `candidate_coeffs`
  on a zero-F row attempts a usize::MAX allocation (OOM/hang)
  instead of returning empty (`remainder_coeffs` handles it
  correctly, inconsistent accessors). Both production callers
  guard with an `f_zero` check, so unreachable normally; an
  API trap for new callers.
- **G2 (sigma, low).** `sigma.rs:148-175` no validation of
  `series_t` entry lengths (assumes exactly b^2; short
  panics, long silently truncates). Caller always builds b^2.
- **G3 (sigma, low).** Sigma minimality / weak-Popov only
  weakly tested (approximant property plus membership tested,
  completeness not). Coverage gap, not a confirmed bug; pivot
  logic inspected standard; matfree head-to-head versus dense
  Toeplitz would catch gross failures.
- **G4 (sigma, low).** Dead `is_pivot`, `pdeg` only an upper
  bound. Neither affects output (degrees recomputed exactly);
  clean except dead code.

### Clean in these files

SS core math (rho enumeration over F_q*, gamma indexing, dual
multipliers, scrambler solve, yhat recovery, exact
B == M * V * diag(yhat) verification, primal y, final rank == k;
no false-accept path). `to_monomial_basis` math. WB division
loop (unsoundness is S3's missing checks, not division).
fastss quadratic solver (all branches brute-force-checked,
including Frobenius sqrt and z^2+z reduction). det3 /
quad_coeffs. Stage 1 completeness (a true triple implies every
3x3 minor vanishes). Dual-test rank-2 case. Stage 4
(original-coordinate construction, zero-vector rejection,
catch_unwind, first verified success wins). Unmix finite
non-degenerate case (failures are exactly U1/U2/U3). Sigma
M-Basis mechanics (residual init, offset invariant, pivot
order, replay order, x-shift, exact degree recomputation).

## What was not fixed, and what changed after the audit

- Original crate: unchanged by the audit.
- NIST build: RNG replaced (CTR_DRBG, AES-256, rejection-sampled
  below), plus `dumpr` / `srcheck` / `rankcheck` / `trialcount`
  debug bins, plus `reuse-holdout-test`. No audit finding above
  was fixed in either build, except F0 (RNG) in the NIST build
  only. In particular, A1/A2, A3, A4/F2 (spool identity), F1
  (puncture seed), and U1/U2/U3 are still present in both
  builds as shipped in v2. Do not read a verify PASS, a spool
  file, or an unmix count without those caveats.
- Later results that change the reading of the audit, not the
  audit itself: with a fresh NIST key, ID-0 nprime=366 flags
  exactly the both-kept dirty columns in trial 0 (62/62), and
  kp28 nprime=112 mate essentiality is dense-proven. Those
  results do not overturn any audit finding; they show the
  flag-none regime that motivated the audit was, at ID-0, a
  trash-key artefact.
